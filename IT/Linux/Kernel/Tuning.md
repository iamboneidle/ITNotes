# 1. Networking
Здесь мы боремся за пропускную способность и скорость обработки соединений.
- **`net.core.somaxconn`**: Размер очереди на «прослушивание» (backlog). Если ваше приложение не успевает обрабатывать новые TCP-сокеты, они будут отбрасываться.
- **`net.ipv4.tcp_tw_reuse`**: Позволяет повторно использовать сокеты, находящиеся в состоянии `TIME_WAIT`. Это критично, когда у вас тысячи коротких соединений в секунду, и вы рискуете исчерпать диапазон эфемерных портов.
- **`net.core.netdev_max_backlog`**: Количество пакетов в очереди на обработку процессором, пришедших с сетевой карты. Помогает при резких всплесках трафика.

# 2. Virtual Memory
Тут мы решаем, как агрессивно система будет использовать диск вместо RAM.
- **`vm.swappiness`**: Контролирует «склонность» ядра вытеснять данные из RAM в swap.
    - `0-10`: Ядро будет до последнего держать данные в памяти (хорошо для БД и Kubernetes).
    - `60`: Дефолт для десктопов.
- **`vm.max_map_count`**: Максимальное количество областей карты памяти, которое может иметь процесс. Этот параметр **обязательно** тюнят для Elasticsearch и некоторых баз данных, иначе они просто упадут при росте индексов.
- **`vm.overcommit_memory`**: Определяет стратегию выделения памяти. Если поставить `1`, ядро будет разрешать выделять больше памяти, чем есть физически (overcommit), надеясь, что процессы не используют всё сразу.
- **`vm.dirty_ratio`**: Процент оперативной памяти, при заполнении которой грязными данными (данные, которые еще не записаны на диск) процесс блокируется до тех пор, пока данные не будут записаны.
- **`vm.dirty_background_ratio`**: Процент памяти, при котором фоновый процесс ядра (`pdflush`/`kworker`) начнет потихоньку скидывать данные на диск.

# 3. Filesystem & Limits
- **`fs.file-max`**: Системный лимит на общее количество открытых файлов. В Linux «все есть файл», поэтому для нагруженного сервера дефолтов всегда мало.
- **`fs.inotify.max_user_watches`**: Лимит на количество файлов, за которыми система может следить в реальном времени. Если вы используете Tailwind, Webpack или агенты сбора логов, которые мониторят тысячи файлов, этот лимит нужно увеличивать.

```shell
sysctl -w net.ipv4.ip_forward=1
# или напрямую в proc
echo 1 > /proc/sys/net/ipv4/ip_forward
# чтобы применить без перезагрузки
sysctl -p
```
