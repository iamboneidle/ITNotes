# 1. Что это
**Суперблок файловой системы** — это критически важная структура данных, которая содержит **метаинформацию** обо всей файловой системе в целом. Его можно представить как «паспорт» или «заголовок» тома.
___
# 2. Что хранит
В зависимости от типа ФС (ext2/ext4, XFS, NTFS), содержимое варьируется, но основные элементы почти всегда одни и те же:
1. **Размер блока (Block Size):** Минимальная единица выделения дискового пространства (обычно 1, 2, 4 КБ).
2. **Общее количество блоков и инодов (inodes):** Сколько всего данных и сколько файлов может вместить диск.
3. **Свободные блоки и иноды:** Счетчики для отслеживания свободного места.
4. **Идентификатор файловой системы (UUID):** Уникальная метка тома.
5. **Метка тома (Label):** Человекочитаемое имя (например, `BackupDrive`).
6. **Время монтирования и последней записи:** Используется для проверок (fsck).
7. **Указатели на корень ФС:** Номер инода корневого каталога (`/`).
8. **Флаги состояния:** Чисто ли размонтирована ФС (clean или dirty).

Операционная система при монтировании диска сначала считывает суперблок. Если он поврежден или прочитан с ошибкой, система **не сможет примонтировать диск**. Вы увидите ошибку вроде: _"Wrong fs type, bad option, bad superblock"_.
___
# 3. Где находится
- **В начале раздела:** Обычно суперблок хранится по смещению **1024 байта** от начала раздела.
- **Резервные копии (Backup Superblocks):** В «жестких» файловых системах (например, ext2/ext3/ext4) суперблок дублируется через каждые несколько групп блоков (часто через 1, 3, 5, 7, 9, 25, 49... групп). Это сделано для восстановления при разрушении основного суперблока.

Восстановить испорченный суперблок можно, указав адрес резервной копии:
```shell
# Найти адреса резервных копий
mke2fs -n /dev/sda1

# Восстановить с указанием бэкапа (например, блок 32768)
e2fsck -b 32768 /dev/sda1
```
