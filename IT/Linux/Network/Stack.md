# 1. Общая схема
Сетевой стек можно разделить на три уровня:
1. **User Space:** Твоё приложение, которое работает с **Сокетами**.
2. **Kernel Space:** Реализация протоколов (TCP/UDP, IP) и управление очередями.
3. **Hardware:** Сетевая карта (NIC) и её драйвер.
___
# 2. Путь входящего пакета
## 2.1. Сетевая карта и DMA
NIC принимает пакет, проверяет контрольную сумму и через механизм **DMA** (Direct Memory Access) кладет его в оперативную память хоста (в специальный кольцевой буфер — **RX Ring Buffer**).
## 2.2. Прерывания и NAPI
Карта генерирует аппаратное прерывание (**IRQ**), говоря процессору: «Есть данные!». Чтобы процессор не сошел с ума от миллионов прерываний (Interrupt Storm), в Linux используется **NAPI** (New API). Ядро переходит в режим опроса (polling) и забирает пакеты пачками.
## 2.3. Обработка в ядре (L2 -> L3)
Пакет превращается в структуру **`sk_buff`** (самая важная структура в сетевом стеке).
1. **L2 (Ethernet):** Ядро проверяет MAC-адрес.
2. **L3 (IP):** Пакет попадает в подсистему **IP**. Здесь вызывается **Netfilter (Prerouting)**. Если пакет прошел, принимается решение о маршрутизации (**Routing Decision**): пакет нам или его надо переслать дальше (Forward)?
## 2.4. L4 (TCP/UDP) и Сокет
Если пакет предназначен нам, вызывается **Netfilter (Input)**. Затем он передается обработчику протокола (например, TCP). TCP проверяет порядковый номер, подтверждения (ACK) и кладет данные в **Receive Buffer** конкретного сокета.
## 2.5. User Space
Приложение вызывает `read()` или `recv()` на дескрипторе сокета, и данные копируются из памяти ядра в память приложения.

# 3. Ключевые компоненты Netfilter (iptables/nftables)
Это те самые «крючки» (hooks) в коде ядра, где мы можем вмешаться в судьбу пакета:
1. **PREROUTING:** До принятия решения о маршрутизации (здесь работает **DNAT**).
2. **INPUT:** Пакеты, идущие локальным процессам.
3. **FORWARD:** Пакеты, проходящие через хост (важно для Docker и K8s).
4. **OUTPUT:** Пакеты, созданные локально.
5. **POSTROUTING:** Перед отправкой в провод (здесь работает **SNAT/Masquerade**).

# 4. Где искать проблемы
- **RX/TX Ring Buffers:** Если они переполнены (смотри `ethtool -S`), значит, ядро не успевает забирать пакеты из карты.
- **SoftIRQs:** Если одно ядро CPU нагружено на 100% в режиме `si` (в `top`), значит, обработка прерываний не сбалансирована (нужно настраивать **RSS/RPS** — распределение пакетов по ядрам).
- **Сокетные буферы (`rmem`, `wmem`):** Если приложение медленно читает данные, буферы TCP переполняются, и окно (Window Size) схлопывается, замедляя передачу. Тюнится через `sysctl net.core.rmem_max`.

# 5. Инструментарий для диагностики
| **Уровень**   | **Инструмент**                              | **Что смотрим**                                                     |
| ------------- | ------------------------------------------- | ------------------------------------------------------------------- |
| **L1/L2**     | `ethtool`, `ip -s link`                     | Ошибки на физике, переполнение буферов карты.                       |
| **L3**        | `ip route`, `iptables -nvL`, `conntrack -S` | Маршруты, дропы в файрволе, состояние conntrack.                    |
| **L4**        | `ss -ntlp`, `netstat`                       | Состояние сокетов (ESTABLISHED, TIME_WAIT), очереди Listen Backlog. |
| **Весь путь** | `tcpdump`, `wireshark`                      | Содержимое пакетов и тайминги.                                      |
