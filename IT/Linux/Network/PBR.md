**Policy Based Routing (PBR)** — это механизм, который позволяет принимать решение о маршрутизации пакета не только на основе IP-адреса назначения (как делает обычная таблица маршрутизации), но и на основе других параметров: IP отправителя, порта, типа протокола или даже меток пакета.
# 1. Как это работает в Linux
В обычном состоянии Linux использует одну таблицу маршрутизации (`main`). С PBR в игру вступает **RPDB (Routing Policy Database)**.

Ядро проверяет пакет по списку **правил (Rules)**. Каждое правило говорит: «Если пакет соответствует критерию X, посмотри в таблицу маршрутизации Y».
**Основные компоненты:**
1. *Selector (Селектор):* Условие (например, `from 192.168.1.10` или `iif eth0`).
2. *Action (Действие):* В какую таблицу отправить пакет (например, `lookup 100`).
3. *Routing Table:* Дополнительная таблица, содержащая свои маршруты и шлюз по умолчанию.
___
# 2. Порядок обработки пакета
Когда пакет попадает в сетевой стек, Linux проходит по правилам сверху вниз (по приоритету):
1. **Rule 0 (local):** Высший приоритет. Содержит маршруты для локальных адресов и broadcast.
2. **Твои кастомные правила:** Здесь ты вставляешь свою логику.
3. **Rule 32766 (main):** Та самая стандартная таблица, которую мы видим через `ip route`.
4. **Rule 32767 (default):** Пустая таблица для пакетов, которые никуда не подошли.

# 3. Практические примеры
## 3.1. Два интернет-канала
У тебя есть медленный, но дешевый канал (eth0) и быстрый дорогой (eth1). Ты хочешь, чтобы весь трафик шел через дешевый, а сервер базы данных — через дорогой.
1. Создаем таблицу для БД: `echo "100 fast_line" >> /etc/iproute2/rt_tables`
2. Добавляем маршрут в эту таблицу: `ip route add default via 1.1.1.1 dev eth1 table fast_line`
3. Создаем правило PBR: `ip rule add from 192.168.1.50 lookup fast_line`

_Теперь пакеты от `192.168.1.50` будут игнорировать таблицу `main` и уйдут через `eth1`._
## 3.2. Маршрутизация по портам
`ip rule` сам по себе плохо умеет работать с портами (L4). Для этого мы используем **iptables** и метки (marks).
1. Метим пакеты (например, весь трафик порта 80): `iptables -t mangle -A PREROUTING -p tcp --dport 80 -j MARK --set-mark 1`
2. Направляем меченые пакеты в спец. таблицу: `ip rule add fwmark 1 lookup web_table`
